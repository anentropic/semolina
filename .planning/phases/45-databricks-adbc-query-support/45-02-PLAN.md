<objective>
Fix the Databricks default-catalog/schema blocker (DBX-02): the arrow-adbc
Databricks driver has no target-catalog/schema kwarg, so an unqualified
`FROM \`sales_view\`` raises `TABLE_OR_VIEW_NOT_FOUND`. The Go driver underneath
parses `catalog=`/`schema=` from the DSN, so adbc-poolhouse's
`DatabricksConfig.to_adbc_kwargs()` must append those URL-encoded query params to
the decomposed `databricks://` URI. This fix lives in the user's SEPARATE
adbc-poolhouse repo; this plan lands it there, then consumes it here via the
pyproject pin.

Purpose: Without the default namespace on the connection, the shared unqualified
`Sales(view="sales_view")` model cannot resolve on Databricks, and recording
(Plan 03) would capture a `TABLE_OR_VIEW_NOT_FOUND` error instead of a result.

Output: the poolhouse `to_adbc_kwargs()` fix + its unit test (in the poolhouse
repo), a chosen and executed consumption mechanism, and an updated
`adbc-poolhouse>=` pin in this repo's pyproject.toml.
</objective>
