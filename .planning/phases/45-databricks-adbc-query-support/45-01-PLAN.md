<objective>
Fix the Databricks ADBC bind-parameter blocker (DBX-01) by inlining WHERE-clause
values as safe SQL literals on Databricks, while keeping Snowflake and DuckDB on
parameterized `?` placeholders (DBX-01b). The injection surface introduced by
inlining is confined to one audited escaper, `Dialect.render_literal`, tested
adversarially (DBX-01c).

Purpose: The arrow-adbc Databricks (Foundry) driver rejects bind parameters
(`NOT_IMPLEMENTED: parameterized queries`), breaking every `.where()` filter.
Literal-inlining keeps `.where()` working identically across backends (the
project's core value) without gating it as NotImplementedError on one backend.

Output: `Dialect.supports_parameterized_queries` capability flag (default True,
False on DatabricksDialect only), `Dialect.render_literal()` (standard-SQL default
+ Spark override), a `SQLBuilder._render_literal_sql()` post-pass, and unit tests
covering DBX-01/01b/01c.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.where()` user value -> generated SQL | On Databricks the value is no longer a bound parameter; it is inlined into the SQL string. This is the only place in Semolina where a user value crosses into SQL text. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01 | Tampering (SQL injection) | `DatabricksDialect.render_literal` inlining WHERE values | mitigate | Single audited escaper: escape `\` -> `\\` FIRST then `'` -> `\'` per Spark string rules; mandatory adversarial unit tests (`O'Reilly`, `a\b`, `'; DROP`, NULL, bool, IN-list) in Task 1. NotImplementedError for unhandled types (fail loud, never mis-escape). |
| T-45-01b | Tampering | Snowflake/DuckDB WHERE values | accept | Stay fully parameterized (`?` + bound params); no inlining. DBX-01b regression tests assert the placeholder path is unchanged. |
</threat_model>
