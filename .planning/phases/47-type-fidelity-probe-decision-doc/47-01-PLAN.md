<assumption_delta_decision>
**Noun now primary:** *the field's result type* — the type a metric's or dimension's values
actually arrive as.

**What generalized:** warehouse introspection metadata used to be the single source of truth for
a field's Python type. The query-time result schema (`adbc_execute_schema`, or a zero-row
execution where the driver does not implement it) is now a second source, and it is the one the
warehouse itself resolves in order to execute.

**Decision: `promote`.** The result schema becomes the primary definition of a field's type;
warehouse introspection metadata is demoted to a labelled, offline-capable *estimate* of it. This
is not "add alongside" — the two are not co-equal. Where they disagree, the result schema wins
and the metadata is recorded as an estimate that missed. Rationale: metadata is what the
catalogue *says*; the result schema is what the driver *does*, and `to_pylist()` converts from
the latter, never the former.

**Invariant encoding this intent:** the canary test in Task 2. If a future change routes the
metadata column and the result column through one source, the asserted `mismatch` becomes
`match` and the test goes red. A comparison that cannot produce a mismatch is not measuring
anything.

**Where the promotion is written down:** plan `47-04`, in `47-DECISIONS.md`. This plan builds
the evidence the promotion rests on; it does not implement the promotion (Phase 48 does).
</assumption_delta_decision>
