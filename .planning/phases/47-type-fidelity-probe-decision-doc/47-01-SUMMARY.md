## The measured row

| Backend | Field | Role | Warehouse type | Metadata provenance | Mapped annotation | Result Arrow type | Result provenance | Python value type | Verdict |
|---|---|---|---|---|---|---|---|---|---|
| duckdb | total_order_value | metric | DECIMAL(38,2) | live | TODO: DECIMAL(38,2) | decimal128(38, 2) | live (execute-schema) | decimal.Decimal | mismatch |

Read it as: the catalogue reports `DECIMAL(38,2)`; Semolina's DuckDB type map has no `DECIMAL` key, so codegen would emit `Metric[Any]` with a TODO comment; the driver resolves the query to `decimal128(38, 2)`; and `to_pylist()` hands the user a `decimal.Decimal`. Three routes, one field, and the annotation names none of what arrives.

## Decisions Made

- **Verdict vocabulary is two values, not three.** See deviation 1 — the plan's action text and its own `must_haves` contradicted each other on what a `TODO: ` annotation scores. Resolved toward `mismatch` because the renderer turns a TODO annotation into `Any`, which names no Python type at all; that is the strongest form of disagreement, not a separate kind of thing. `classify_verdict()` documents this in its docstring.
- **The probe route is a measurement, not a label.** `probe_schema` returns `ProbeResult(schema, route)` and the artifact renders `live (execute-schema)`. Had DuckDB refused, the same cell would read `live (zero-row)` without anyone editing prose.
- **The metadata raw type is re-measured, never parsed back out.** `describe_raw_types()` re-runs the same `DESCRIBE SELECT * FROM semantic_view(...)` that `DuckDBEngine.introspect()` runs, and keeps column 1 verbatim. Parsing the raw type out of the `TODO: ` prefix would only work for types the map already misses, which is exactly the population the artifact must not special-case.
- **The probe SQL is built, never pasted.** `probe_sql_for()` drives `DuckDBSQLBuilder` from a `TypeFidelityView` model. RESEARCH.md measured that a hand-written `SELECT SUM(...)` over the base table reports `HUGEINT`/`decimal128(38, 0)` where the `semantic_view()` route reports what users actually receive.
- **Metric names in the fixture DDL deliberately differ from column names** (`total_order_value` over `order_total`). `semantic_views` 0.12.0 rejects a metric that collides with a dimension or column name — the same change that broke `tests/unit/test_pool.py` during Phase 46.
