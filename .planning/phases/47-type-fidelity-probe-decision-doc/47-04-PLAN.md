<assumption_delta_decision>
**Noun now primary:** *the field's result type*.

**What generalized:** warehouse introspection metadata was the single source of truth for a
field's Python type. The query-time result schema — `adbc_execute_schema`, or a zero-row execution
where the driver does not implement it — is now a second source, and it is the one the warehouse
itself resolves in order to execute the query.

**Decision: `promote`.** The result schema becomes the primary definition of a field's type;
introspection metadata is demoted to a labelled, offline-capable *estimate* of it. Not
"add alongside": the two are not co-equal, and treating them as co-equal is what produced three
backends disagreeing three ways about the same decimal column. Where they disagree the result
schema wins, and codegen records which route produced the annotation. Rationale: metadata is what
the catalogue says; the result schema is what the driver does, and `to_pylist()` converts from the
latter and never from the former.

**Accepted consequence, not accepted debt:** metadata does not disappear. It remains the documented
fallback for offline codegen and for the two cases where the probe is unavailable — Snowflake with
bind parameters, and any driver answering NOT_IMPLEMENTED. That is a demotion with a named
fallback, not a co-primary.

**Invariant encoding the intent:** the canary test from plan `47-01` and the raw-Arrow bypass test
from plan `47-03`. If a future change re-derives result types from metadata, both go red.

**This is the plan that writes the promotion down**, in `47-DECISIONS.md` § "Which source of truth
codegen uses". Phase 48 implements it.
</assumption_delta_decision>

<reversibility>
- **Decimal policy = `decimal.Decimal`.** Rated `costly`, not one-way. It is the specification for
  Phase 48's TYPE-03, and reversing it after Phase 48 ships changes the annotation every user's
  generated model carries for money columns. It is not one-way because the project is pre-1.0, the
  runtime value is already a `Decimal` today, and reversing would be a codegen change plus a
  regeneration, not a data migration. No `checkpoint:decision` is inserted; the
  `checkpoint:human-verify` in Task 3 is where a human accepts all three policy calls together,
  which is the right granularity — they interlock.
- **Source of truth = probe primary, metadata fallback.** Rated `costly` for the same reason: it
  shapes Phase 48's `--check` and Phase 50's DTO codegen. Reversible at the cost of rewriting those
  two phases' plans, which do not exist yet.
- **Metric nullability = uniform stance.** Rated `reversible`. Narrowing COUNT later is a
  one-function change in the type map, and the doc records COUNT as a known over-approximation
  precisely so narrowing it later is a refinement rather than a contradiction.
- **User-facing page at `docs/src/explanation/type-fidelity.rst` alongside the normative
  `.planning/` doc.** Rated `costly`: a published page is a URL, and the split means two documents
  can drift. Taken because the consumers differ — Phases 48 and 50 need a dated, precise,
  citation-carrying specification, and a user who finds `Decimal` in a generated model needs a
  short explanation with no planning vocabulary in it. The `.planning/` doc is normative; the docs
  page is derived from it and links nowhere into `.planning/`.
</reversibility>
