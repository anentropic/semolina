<objective>
Document the async surface for the audience it was built for: data and analytics engineers
standing up a BI reporting backend, who came here because their web framework is async.

CLAUDE.md makes documentation mandatory for API-surface changes, and this phase adds public API —
a constructor, a registry pair, a query method, and a cursor type. Four existing pages carry the
change: the web-API how-to currently shows only synchronous handlers, the streaming how-to shows
only synchronous iteration, the connection-pools how-to describes engine lifecycle and pool
sizing in sync-only terms, and the installation tutorial does not mention the new extra.

One thing here must be said plainly rather than softened. The sync cursor has a finalizer that
returns a leaked connection to the pool; the async cursor cannot have one, because closing
requires awaiting and an un-awaited coroutine in a finalizer produces a never-awaited warning.
So on the async path a cursor closed by neither `async with` nor `aclose()` holds its pool
connection permanently. That is a real regression against the sync path and the docs must state
it, not paper over it.

Purpose: make the async surface discoverable and its one sharp edge visible.
Output: async sections in three how-to pages, the extra documented in the installation tutorial,
and a clean docs build under warnings-as-errors.
</objective>
