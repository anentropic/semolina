<objective>
Prove that cancellation reaches the warehouse, and make the two-loop-backend claim structural
rather than a snapshot.

ASYNC-06 is delivered entirely upstream. poolhouse pairs a watcher task parked on an event with
the worker thread, fires the driver's cancel from inside a shield when the surrounding scope is
cancelled, runs poison recovery off a dedicated one-token limiter so it cannot deadlock behind
the worker it just aborted, tracks an aborted-by-us flag so the driver's interrupt is not
mistaken for a real error, and unwraps the resulting exception group. Semolina writes none of
that. RESEARCH Finding 2 is explicit: plan ASYNC-06 as a **test** task, not an implementation
task.

What Semolina can still break is transparency. On the cancel path poolhouse swallows the
driver's interrupt and re-raises the framework cancellation, which under asyncio is a
`BaseException` and not an `Exception`. A `try/except Exception` in Semolina would let it
through unnoticed; a `try/except BaseException` that logged and returned would eat it. Plan 02
wrote the only permitted handler shape — release the resource, then always re-raise — and this
plan is where that discipline gets an executed proof.

The second half closes an easy-to-lose property. ASYNC-05 requires the async tests green under
both asyncio and Trio, and Plan 02 wired a module-local parametrized backend fixture into each
async test module. Nothing stops a later module from omitting it and silently covering asyncio
only. This plan makes that omission fail the build.

Purpose: turn "cancellation reaches the driver" and "green under both backends" from claims into
gates.
Output: a cancellation test module against a real DuckDB driver, and a structural loop-matrix
invariant over the whole test tree. No library code changes.
</objective>

    Write two families of test, in this order, because they carry different risk.

    **The deterministic family, which must never be flaky.** Enter a cancel scope, cancel it
    immediately, and then await `engine.aexecute(query)` inside it against the existing
    `async_duckdb_engine`. The first checkpoint inside `aexecute` observes the pending
    cancellation, so this needs no timing at all. Assert the cancellation propagates, assert no
    cursor was returned — a cancelled call returning a cursor instead of raising is Pitfall 2's
    first warning sign — and assert the inner pool's `checkedout()` is 0 afterwards, which is
    what proves the `except BaseException` arm released the slot rather than swallowing.
    Then the mid-stream variant: open a cursor normally, consume one row, and cancel the scope
    while inside the `async for` body. Assert the cancellation propagates and that no second
    exception surfaces from the cursor's teardown to mask it — a `ConnectionBusyError` raised out
    of teardown is Pitfall 1's warning sign and would mask the cancellation the caller needs to
    see.

    proves the *driver* was reached rather than merely that the client stopped waiting. Add a
    session-scoped fixture building a file-backed DuckDB database whose semantic view is
    deliberately expensive to aggregate: a few million narrow rows, with the metric defined as a
    CPU-heavy aggregate expression over a per-row string construction rather than a plain column
    sum. Do **not** use a sleep, and do not use a wall-clock threshold as the assertion. Instead
    make the fixture measure one full uncancelled aggregate once and record the duration; if that
    measured duration is below two seconds, raise the row count or the per-row expression cost

    test that races is not.

    the framework's cancellation type — expect the driver's own interrupt error to be swallowed

    pass for the wrong reason or not at all. Then assert the pool recovered by running a fresh,
    cheap query on the same engine and getting rows back: poolhouse invalidates the aborted
    connection for poison recovery, so a working follow-up query is the observable evidence that
    the abort reached the driver and was cleaned up rather than that the call was abandoned.
    Record the measured duration and the deadline in the SUMMARY.
