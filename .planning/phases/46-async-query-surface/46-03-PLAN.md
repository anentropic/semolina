<objective>
Run the D-16 spike: prove one existing cassette replays end to end through the async path,
for both warehouse dialects, without recording anything.

D-15 declared cassette replay through the async path viable, and CONTEXT.md made that a
user-set gate — if replay could not intercept poolhouse's async cursor, the phase stops and
pytest-adbc-replay gets updated first. RESEARCH Finding 9 promoted D-15 from structural
inference to verified on three independent grounds: the plugin's patch point is a module
attribute on the driver module, which is process-global and therefore visible from inside
poolhouse's offload worker thread; the plugin contains no async code at all and no
thread-local state; and its replay cursor returns a real Arrow reader, which structurally
satisfies the protocol poolhouse's async reader wraps by composition. So this spike is now
expected to pass rather than a genuine coin flip — but it converts three static confirmations
into one executed test, which is the point.

D-16 asks for this as the phase's first task. It cannot literally be first: it needs
`create_async_engine`, `AsyncEngine.aexecute`, and the async cursor to exist. It is therefore
the lowest-numbered plan in the earliest wave that can run it. Plans 04 and 05 share this
wave and build nothing on the replay assumption — they are DuckDB, registry, and cancellation
work — so running them in parallel does not violate D-16's intent. Plan 06's cross-dialect
documentation claims do depend on this result, and Plan 06 is a later wave.

**If this plan fails, stop the phase.** Do not work around a cassette miss by re-recording
against a live warehouse or by loosening the match. A miss means either the async path
generates different SQL than the sync path (contradicting D-04) or replay cannot intercept the
async stack (contradicting D-15). Both are findings that change the plan, not obstacles to
route around.

Purpose: close RESEARCH Assumption A2 by execution, and give Snowflake and Databricks — where
no live async verification is possible in this environment at all — real coverage.
Output: two replay-only async fixtures, four copied named cassettes, four replay tests.
</objective>
