<objective>
Deliver the two dataframe entry points and make every optional-dependency failure on the
synchronous cursor say what to install.

Purpose: `fetch_df()` and `fetch_polars()` already exist on both layers underneath —
`adbc_driver_manager.dbapi.Cursor` implements them, and poolhouse offloads them through the
pool limiter with cancellation and poison recovery. RESULT-01 is therefore four passthrough
lines across this phase, and almost none of the work. RESULT-02 is the work, because both
lower layers *deliberately* refuse it: poolhouse states that the driver imports pandas inside
the worker so a missing install surfaces the native `ModuleNotFoundError` unchanged, with no
pre-check and no wrapping, and ADBC's `fetch_polars` does a bare `import polars`. A user
without polars currently gets a ten-frame traceback ending in someone else's module.

There is a second, older hole this closes: Semolina declares `pyarrow` only inside the
`[duckdb]` extra, so a base install plus `[snowflake]` can already reach
`fetch_arrow_table()` today and fail with ADBC's `This API requires PyArrow to be installed`.

Output: `fetch_df` and `fetch_polars` on `SemolinaCursor`, and a guard on each of the four
Arrow/dataframe methods for exactly what that method imports.
</objective>

<flagged_assumptions>
The phase's full unresolved-edge audit is in `49-01-PLAN.md` § `<flagged_assumptions>` (9
probe items = 2 authored + 7 flagged; no silent drops). This plan owns two of the seven.

**FLAGGED — RESULT-01, `unclassified`, unresolved.** Planner assumption: the edge is call
ordering rather than return type. `fetch_polars()` takes the Arrow stream handle and must be
the first consuming call on a cursor; `fetch_record_batch` then `fetch_polars` was measured
failing with `Result set has been closed or consumed`, and `fetch_polars` twice likewise.
Task 1 documents it and Task 2 tests it. Whether `fetch_df()` carries the same constraint was
measured as "no" (`fetch_df` then `description` works), but that is an observation about
adbc-driver-manager 1.10.0/1.12.0 and not a contract — do not document it as one.

**FLAGGED — RESULT-02, `unclassified`, unresolved.** Planner assumption: the edge is *which*
package each method actually needs, and the answer is not uniform. `fetch_polars()` needs
polars but not pyarrow. `fetch_df()` needs pandas, and almost certainly pyarrow as well
because ADBC's implementation goes through a pyarrow reader — but that is the planner's
reading of the source, and Task 1 requires the executor to confirm it by reading ADBC's own
`fetch_df` before writing the guard. A guard for a package the method does not import refuses
a call that works, which is a worse failure than the one RESULT-02 exists to fix.
</flagged_assumptions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ADBC driver internals -> user-visible error | A missing optional package currently surfaces as a ten-frame traceback ending in a third-party module |
| result stream handle -> multiple consumers | One cursor owns one Arrow stream; a second consumer gets a closed result |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-49-08 | Information disclosure | native `ModuleNotFoundError` / `ProgrammingError` traceback | low | mitigate | The guard replaces a traceback through ADBC and poolhouse internals with a one-line message naming the package and the install command. It leaks nothing sensitive today; the fix is usability with a small disclosure benefit, which is why it is rated low rather than ignored. |
| T-49-03 | Denial of service (pool exhaustion) | `fetch_polars` ordering against a live reader | medium | mitigate | The first-consuming-call rule is documented in the docstring and pinned by an ordering test, so a caller who breaks it gets the driver's own message rather than a wedged cursor. |
| T-49-01 | Tampering / Information disclosure | `fetch_df` decimal degradation | medium | accept | `fetch_df()` renders a warehouse decimal as an `object` dtype holding `Decimal` (measured at pandas 2.3.3), and `fetch_polars()` was measured by Plan 03. Both are the downstream library's behaviour, documented rather than corrected — correcting it would be exactly the value coercion 47-DECISIONS.md Decision 1 prohibits. |
| T-49-04 | Tampering (supply chain) | `[pandas]` / `[polars]` extras | high | transfer | Both enter through Plan 01's extras, its legitimacy checkpoint and its committed lock. This plan adds no dependency. |
