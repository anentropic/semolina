<objective>
Give the async cursor the same four methods the synchronous one now has, keeping every one
of Phase 46's hard-won rules about readers, offloading and teardown intact.

Purpose: the async twin is where D-05 stops being a stylistic preference. On the sync cursor,
writing `iter_into` as a generator function is merely wrong. On the async cursor it is also
tempting, because the obvious way to get a schema is `await self.fetch_record_batch()` — and
the moment `iter_into` needs an await, it becomes a coroutine and the check can no longer
happen at the call. `cursor.description` is the way out: a plain synchronous property on both
cursors, free, and creating no reader. That single choice is what makes the async half
possible, and Plan 01 already built the pre-check around it.

The second reason this is its own plan: `tests/unit/test_dto_async.py` is not a normal test
module. `tests/unit/test_asyncio_trio_matrix.py` walks every test file with `ast.parse` and
fails the build for any module containing an `async def test_*` that does not carry both a
module-level anyio `pytestmark` and a module-level `anyio_backend` fixture parametrised over
both backends, in a very specific syntactic shape. Getting that wrong fails a test that is
about a different file.

Output: `into`, `iter_into`, `fetch_df` and `fetch_polars` on `AsyncSemolinaCursor`, guards
on all four, and a two-backend async test module.
</objective>

`iter_into` is a PLAIN method: `def iter_into(self, model: type[_M], *, validate: bool =

pre-check off `self.description`, then `return self._aiter_into_impl(model,

an `async def` would defer the check to the first `await`, and an `async def` containing
`yield` would defer it to the first `async for`.

`_aiter_into_impl` is the async generator function:
`async def _aiter_into_impl(self, model: type[_M], *, validate: bool) -> AsyncIterator[_M]`.

`convert()` / `iter()` take no `validate=` keyword, so setting it anywhere else is a silent
no-op. Obtain the reader with `reader = await self.fetch_record_batch()`, NOT
`self._cursor.fetch_record_batch()`: going through the cursor's own delegate is what records
the reader so `aclose()` can close it before the cursor, and a reader the cursor did not
record leaks its pool slot silently because the teardown errors are suppressed. Drive it with
`await reader.__anext__()` inside a loop that carries over `__anext__`'s three behaviours
verbatim — `StopAsyncIteration` ends iteration, an `OSError` from a stream drained elsewhere
is normalised to termination, and a `batch.num_rows == 0` batch is skipped rather than ending
the stream. Per batch, iterate `converter.iter(batch)` synchronously and `yield` each DTO
individually (D-03); the conversion itself is CPU-bound Rust over an already-materialised
batch and needs no offload of its own.

`fetch_record_batch`'s docstring: one reader per cursor and a repeat call returns the reader
already in flight, so pick one consumption pattern per cursor; the reader locks its connection
for its whole lifetime and draining it does not clear the lock; and — the sentence that
matters most here — the async cursor has NO `__del__` rescue, so a cursor closed by neither
`async with` nor `aclose()` leaks its pooled connection permanently. Say that `iter_into`
checks the schema at the call and not on the first `async for`, and why. `Example:` blocks
use `.. code-block:: python` and never `>>>`.
