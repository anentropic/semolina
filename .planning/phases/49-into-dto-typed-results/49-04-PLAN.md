<objective>
Prove DTO-05 with the only two mechanisms that can prove it: a real clean venv for what an
install contains, and a child interpreter for what an import pulls.

Purpose: DTO-05 is a claim about a *default install*, and CI installs everything. A
`find_spec` monkeypatch can prove that the guard raises when a package is missing — Plan 01
already tests that — but it cannot prove that a package is missing, because it fakes the very
observation being made. CI already carries the right instrument: a `packaging-smoke` job that
builds an extras-free venv and asserts absence directly, added for ASYNC-04. Extending it is
a smaller and stronger change than inventing a new mechanism.

Output: `tests/unit/test_dto_packaging.py` covering the declaration half and the lazy-import
half, two new public-surface assertions, and extended `packaging-smoke` steps whose claims
are measured before they are written.
</objective>

must be sufficient on its own" — is deliberately NOT covered: nothing here asserts that

contract, surfaced rather than papered over. If a reviewer decides it matters, the fix is a
`pyproject.toml` change (making `[arrowmodel]` reference `semolina[pyarrow]`, exactly as
`[duckdb]` now does), not another test.

Second assumption, recorded because it shapes Task 1: `import semolina` currently pulls
`pyarrow` and `pandas` into `sys.modules` in the dev venv — measured, not inferred. Neither
can be asserted absent by the child-interpreter test. Task 1 records that as a docstring
rather than dropping the coverage silently, and Task 2 checks whether the same holds in a
clean base venv, where the answer may well differ.
