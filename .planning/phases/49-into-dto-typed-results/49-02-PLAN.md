<objective>
Expand the proven `.into()` slice sideways: the streaming twin, and the full breadth of the
structural pre-check that Plan 01 only exercised on one column.

Purpose: `iter_into` is where the phase's subtlest requirement lives. arrowmodel's own
`Model.iter(batch)` is a generator function — measured returning without raising, then
raising on the first `next()`. If Semolina copies that shape, a user who builds a bad DTO
finds out several frames away from the call that caused it, and D-05 is silently unmet with
a green suite. The pre-check's breadth is the other half: it must be confident enough to
catch Decimal into `float` and quiet enough that a nested struct, a `pydantic.JsonValue`, or
an unmapped Arrow type does not start raising on a call site that worked yesterday.

Output: `SemolinaCursor.iter_into` with eager checking and lazy production, and
`tests/unit/test_dto.py` covering every rule D-07 through D-11 plus PD-02 with fakes rather
than a warehouse.
</objective>

Add two methods to `src/semolina/cursor.py`, immediately after `into`.

Both live on the cursor, not on `Query` — per D-02 this phase adds no `Query.into()` /
`Query.iter_into()` terminal, and the pre-check runs on this path too per D-06, always, off
the schema already in memory.

The public one is a plain method, NOT a generator function:
`def iter_into(self, model: type[_M], *, validate: bool = False) -> Iterator[_M]`. Its body
contains no `yield` at all. In order: `_require("pyarrow", "pyarrow")`,
`_require("arrowmodel", "arrowmodel")`, a function-local
`from .dto import check_result_schema` then `check_result_schema(self.description, model)`,
then `return self._iter_into_impl(model, validate=validate)`. Add `Iterator` to the
`TYPE_CHECKING` imports from `collections.abc`. This shape is the entire point of D-05: a
`def` containing `yield` runs no body until the first `next()`, and arrowmodel's own
`Model.iter(batch)` was measured doing exactly that — returning without raising, then raising
on the first `next()`.

The private one is the generator function:
`def _iter_into_impl(self, model: type[_M], *, validate: bool) -> Iterator[_M]`. Import
`ArrowModelConverter` function-locally and construct it ONCE before the loop as
`ArrowModelConverter(model, validate=validate)` — the converter compiles its alias-aware
field map at init and reuses it across batches, and its `convert()` / `iter()` take no
`validate=` keyword, so passing it anywhere else is a silent no-op. Then obtain
`reader = self.fetch_record_batch()` and drive it with an explicit `while True` +
`read_next_batch()` loop rather than `for batch in reader`, so the two behaviours the
existing `__next__` loop encodes are preserved verbatim: a `batch.num_rows == 0` batch is
skipped and iteration continues, and an `OSError` from a drained reader is normalised to
termination the same way `StopIteration` is. Per batch, `yield from converter.iter(batch)`
so DTOs are yielded individually (D-03) while conversion happens a whole batch at a time.
Never hand the reader itself to arrowmodel — a `RecordBatchReader` is rejected with
`ValueError: Expected an object with dunder __arrow_c_array__`.

Cast the converter's output the same way `into` does: `ArrowModelConverter.iter` is typed
`-> Iterator[BaseModel]`, so recover the concrete type with `typing.cast` rather than a
suppression comment.

The docstring restates, in `fetch_record_batch`'s own words, the two lifetime rules a
streaming consumer must know: the returned iterator shares this cursor's single underlying
stream, so pick one consumption pattern per cursor because a second consumer picks up where
the first stopped; and the cursor must outlive the iterator. Add a sentence saying the
schema check happens at the call rather than on first iteration, and why that matters. Use
`.. code-block:: python` for the `Example:`, never a `>>>` block.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| warehouse -> Arrow batch -> DTO field | Untyped warehouse data crosses into a typed Python object, one batch at a time |
| streaming reader -> pooled connection | An unconsumed or unclosed iterator holds the cursor's single reader, which locks its connection |
