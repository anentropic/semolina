Widen `Dialect.render_literal` and `DatabricksDialect.render_literal` to accept
`datetime.date`, `datetime.datetime`, and `decimal.Decimal`, closing DBX-04.

pass fails loudly — so it lands RED first, then GREEN, in two commits.

adversarial tests in both `TestRenderLiteralStandardSql` and `TestRenderLiteralDatabricks`,
an end-to-end inlining assertion in `TestDatabricksLiteralInlining`, and two re-pointed
negative guards.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user filter value -> inlined SQL text | `DatabricksDialect.supports_parameterized_queries = False`, so every `.where()` value is interpolated into the SQL string instead of bound — this is the phase's only untrusted-input-into-SQL path |
| Python `datetime`/`Decimal` -> Spark literal grammar | A value that renders in the wrong grammar silently changes which rows come back |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48-05 | Tampering | `render_literal` new `date`/`datetime` branches | high | mitigate | A user-supplied value reaching inlined SQL is the classic injection surface (ASVS V5). `date.isoformat()` and `datetime.isoformat()` emit only the ISO-8601 alphabet, but both are still routed through the SAME quoted-and-escaped string expression the `str` branch uses, so `sql.py:91-93`'s single-audited-site claim stays true. Adversarial tests mirroring the existing `O'Reilly` / `a\b` / `'; DROP` cases assert no unescaped quote can appear. |
| T-48-06 | Tampering | `render_literal` `Decimal` branch | high | mitigate | `format(value, "f")` emits only digits, an optional leading `-`, and at most one `.`. Non-finite values (`NaN`, `Infinity`) have no SQL literal at all and are rejected with `ValueError` before rendering, so no `nan` token reaches the SQL text. Asserted by test. |
| T-48-07 | Tampering | branch order (`datetime` before `date`) | high | mitigate | A `date`-first branch truncates a timestamp to `DATE '...'` — no error, no traceback, wrong rows. This is a silent correctness/authorisation-adjacent failure (a filter that matches more rows than intended). Guarded by an explicit test asserting `10:05` survives, and by the in-file `bool`-before-`int` precedent cited in the action. |
| T-48-08 | Tampering | Spark DECIMAL-vs-DOUBLE grammar | medium | mitigate | An exponent form (`1E+2`) parses as DOUBLE in Spark, changing the comparison's type coercion. `format(value, "f")` guarantees fixed-point output so no exponent ever reaches the literal. Asserted by `test_decimal_exponent_form_stays_decimal`. |
| T-48-09 | Information disclosure | `ValueError` / `NotImplementedError` messages | low | accept | The existing messages interpolate `{value!r}` and `type(...).__name__`. A filter value can appear in an exception message. This is pre-existing behaviour on the float branch, the messages go to the caller who supplied the value, and nothing is logged to a shared sink (ASVS V7). |
| T-48-SC | Tampering | package installs | low | accept | This plan installs no packages. `48-RESEARCH.md` § "Package Legitimacy Audit" records zero added dependencies for the phase. |
</threat_model>
