<objective>
Ship `semolina codegen --check`: a mode that reports whether a committed model's annotations
still match the warehouse's current result schema, without fetching a single row.

TYPE-07 is the one requirement in this phase with no specification behind it — 47-DECISIONS.md
never names the CLI surface. This plan implements the design `48-RESEARCH.md` § "TYPE-07" and
`48-CONTEXT.md` D-01/D-02/D-09 settle: a `--check` flag on the existing `codegen` command,
per-field comparison against a probed result schema, the committed model read by AST, probe
primary with a labelled metadata fallback, a per-field table to stderr, and a new
`EXIT_ANNOTATION_DRIFT = 5`.

Purpose: after this phase changes what codegen writes, a user needs a way to find out when
their committed model has gone stale — and the only honest answer is the query-time result
schema, which is what Decision 3 promotes to primary.

Output: two new pure-ish modules (`model_reader.py`, `annotation_check.py`) that are testable
without a CLI runner, the CLI wiring, and live-DuckDB acceptance tests covering match, drift,
route reporting, and the no-rows guarantee.
</objective>

**FLAGGED — TYPE-07, category `unclassified`, status `unresolved`.** The probe could not
classify what edge TYPE-07 ("a `--check` mode that reports whether a committed model's
annotations still match the warehouse's current result schema, without executing a query for
rows") has, which is unsurprising: TYPE-07 has no specification behind it at all —
47-DECISIONS.md never names a CLI surface. The whole design is the researcher's
recommendation adopted as a planner decision. The assumptions a reviewer should check rather
than accept:
  1. **The comparison is per-field against a probed schema, not a regenerate-and-byte-diff.**
     Byte-diff is far cheaper but compares against the METADATA route, which does not satisfy
     TYPE-07's wording ("still match the warehouse's current *result schema*"). Named here so
     nobody "simplifies" it back.
  2. **The canonical query is unfiltered** — all metrics plus all dimensions, no WHERE.
     Snowflake refuses `ExecuteSchema` with any bound parameter, and `--check` has no filter to
     apply. If a view's planner behaves differently for a filtered query, `--check` measures the
     unfiltered shape and says nothing about the filtered one.
  3. **The committed model is read by `ast.parse`, not by import.** Import works — `__orig_class__`
     survives at runtime — but it executes arbitrary user code and returns a `ForwardRef` for a
     `JsonValue`-annotated field. The AST route is the safer of two working options, not the
     only one.
  4. **Nothing here is verified on Databricks** (D-09), and the Snowflake half is narrowed to
     the comparison core because no Snowflake introspection cassette exists in this repo. Both
     limits are stated in Task 2's action and must appear in the summary.
</flagged_assumptions>

Create `src/semolina/codegen/model_reader.py`. It reads a committed generated model file and
returns its declared field annotations as text. It must NOT import the module: importing
executes arbitrary user code, requires the file to be an importable package member, and (for
a `JsonValue`-annotated field) returns a `ForwardRef` rather than the source text. `ast.parse`
has none of those problems and is the route `48-RESEARCH.md` recommends.

Define two frozen dataclasses. `CommittedField` carries `name: str`, `field_class: str`
(`"Metric"` / `"Dimension"` / `"Fact"`), `annotation: str` (the subscript exactly as written),
and `source_name: str | None`. `CommittedModel` carries `class_name: str`, `view_name: str`,
and `fields: dict[str, CommittedField]` in source order.

`read_committed_model(path: pathlib.Path) -> list[CommittedModel]` reads the file with
`path.read_text(encoding="utf-8")`, parses it with `ast.parse(source, filename=str(path))`,
and walks the top-level `ast.ClassDef` nodes. For each class, read the `view=` value from
`node.keywords` (an `ast.keyword` whose `arg == "view"` and whose `value` is an `ast.Constant`
holding a `str`); skip any class that has none. Inside the class body, each field is an
`ast.Assign` with a single `ast.Name` target whose `value` is an `ast.Call` whose `func` is an
`ast.Subscript`. From that node take: the field class from the subscript's `value` (an
`ast.Name`, whose `id` must be one of `Metric` / `Dimension` / `Fact` — skip anything else),
the annotation from `ast.unparse(subscript.slice)`, and `source_name` from a `source=` keyword
in the call when present. Skip a bare `Metric()` with no subscript rather than crashing — the
documented untyped shorthand is legal and simply has no annotation to compare; represent it
with `annotation = "Any"` so it compares as the untyped fallback it is.

Wrap `SyntaxError` from `ast.parse` in a `ValueError` whose message names the path, the line
number, and the original message, so the CLI can turn it into a clean exit code rather than a
traceback. Wrap `OSError` from `read_text` the same way.

Follow the `codegen/` package conventions from `type_map.py`: module docstring stating the
contract and what a miss means, `from __future__ import annotations`, full Google docstrings

`check_view` does four things:

1. **Enumerate the fields.** Call `engine.introspect(view_name)`. Use it for field names,
   roles, `source_name`, and — only as the fallback — `data_type`. Enumerating from the
   warehouse rather than from the committed model is what lets the report distinguish "field
   removed from the view" from "field added to the view"; both become drift rows.

2. **Build the canonical query.** Construct a `SemanticView` subclass at runtime from the
   introspected fields — `SemanticViewMeta(class_name, (SemanticView,), namespace, view=view_name)`
   with an untyped `Metric()` / `Dimension()` / `Fact()` per field (plus `source=` where
   `IntrospectedField.source_name` is set). Untyped is correct here: `Metric()` is documented
   shorthand for `Metric[Any]()` and the builder needs names and roles, not annotations. Then
   `dialect.create_builder().build_select_with_params(Model.query().metrics(...).dimensions(...))`,
   exactly as `tests/type_fidelity_probe.py:747` `probe_sql_all` already does. The query is
   UNFILTERED — all metrics plus all dimensions, no WHERE — because Snowflake refuses
   `ExecuteSchema` with any bound parameter and `--check` has no filter to apply. Never build
   this SQL by f-string interpolation of catalogue names; the builder and
   `duckdb.py`'s `_sql_str_literal` are the only two sanctioned paths.

3. **Probe.** Open a cursor via `engine.connect()` and call
   `semolina.codegen.probe.probe_schema(cursor, sql, params)`. On DuckDB, issue TWO probes and

   Use `"(absent)"` for a side that has no value. Never place a row VALUE in a report field —
   only names, type strings and routes.
